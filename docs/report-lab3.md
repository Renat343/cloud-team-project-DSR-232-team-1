## 11. Вывод
Issues помогают фиксировать и распределять задачи. Отдельные ветви позволяют вносить изменения независимо от основной версии проекта. Commits сохраняют историю изменений. Pull Requests позволяют контролировать объединение изменений с основной ветвью. Merge завершает рабочий цикл и переносит проверенные изменения в `main`.

## 12. Ответы на контрольные вопросы

### 1. Для чего в командном GitHub-проекте используются Issues?
Issues используются для постановки, описания, распределения и контроля задач внутри репозитория.

### 2. Почему изменения рекомендуется выполнять в отдельной ветви, а не напрямую в main?
Отдельная ветвь позволяет изменять проект независимо от основной версии и проверять результат до объединения с `main`.

### 3. Что такое Pull Request и какую роль он выполняет?
Pull Request — это запрос на объединение изменений из одной ветви в другую. Он позволяет обсудить и проверить изменения перед merge.

### 4. Чем отличаются Comment, Approve и Request changes?
- Comment — обычный комментарий к изменениям без итогового решения.
- Approve — одобрение изменений.
- Request changes — запрос на доработку перед объединением.

### 5. Как связаны Issue, ветвь, commit, Pull Request и merge?
Сначала создаётся Issue с задачей, затем отдельная ветвь. В ветви выполняются изменения и фиксируются commit. После этого создаётся Pull Request, а после проверки выполняется merge в `main`, связанный Issue закрывается.
